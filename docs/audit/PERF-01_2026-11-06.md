## What this shows
- The "541.60 kB hadith chunk" warning is the **uncompressed** size. Over the network it is about 110 kB. It is already a separate lazy chunk, loaded only on the Hadith screen, but it is also saved for offline at install (the owner's offline-first rule), so it counts in the first download.
- Old-format `.woff` fonts are already left out of the offline list when `.woff2` exists (`tools/precache.ts`, `tests/precache.test.ts`), so fonts are not downloaded twice.
- The whole offline save is about 1.2 MB compressed. No change to the code was made: shrinking `hadithPack` or `i18n` further (for example per-language packs) would not reduce what an offline-first install must save, only parse time, and it would add offline risk.

## Decision and what stays open
- No code change for PERF-01 now; the cost of the saved download is small and the offline behaviour is preserved.
- Still open (needs the owner's phone, so it stays in OWNER-01): the real cold-download size and time on the phone's mobile data. A simple way: Chrome > site settings for the app address > "Storage used" after the first visit shows the saved size.
- A later option if the owner wants a smaller first install: load the Hadith pack only when first opened and save it then (breaks "everything offline from the first visit"; needs an owner decision).
