## Update rules

- Status: **Pending** (বাকি), **In progress** (চলছে), **Needs verification** (যাচাই বাকি), **Done** (সম্পন্ন), **Blocked** (অবরুদ্ধ; acceptance states what is missing).
- Priorities: P0 confirmed urgent loss/exposure, P1 data/recovery/reliability, P2 correctness/validation/maintenance, P3 optional improvements. Priority is not permission to bypass a human gate.
- One row per active work package. Add smaller child IDs here when implementation starts; do not create a second tracker in TODO or issues. Owner identifies responsibility, not a fabricated assignee.
- Done requires dated, linked acceptance evidence for the actual behavior. Automation cannot close phone, usability, licensing or reviewer gates. Existing feature reports are historical until the assigned verification package resolves them.
- Stable previous IDs are preserved in [legacy-task-map.json](legacy-task-map.json). Each maps to one active package; the original row, status, evidence and dependencies stay in the snapshot. Mapping consolidates duplicate work descriptions, not completion claims. Historical `Built+Linked+Tested` is not silently promoted to current Done.
- Append evidence/status changes to [PLAN_CHECK_LOG.md](PLAN_CHECK_LOG.md). Run `node tools/check_plan.mjs` after edits. The original Register v2_0 remains read-only.
