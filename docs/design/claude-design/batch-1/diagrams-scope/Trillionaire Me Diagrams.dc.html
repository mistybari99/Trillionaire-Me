Trillionaire Me · Diagram system

Ten diagrams, one visual language

Source: Canonical Spec v2.0 and CLAUDE.md from the repository. Each diagram answers where you are now, what happens next and what changes when real life differs from plan.

Legend: node type
Rectangle: core module or process
Stadium: goal, stage or milestone
Diamond: decision or approval
Dashed: external service or future phase
Dotted arrow: feedback or change loop
Legend: status tags
[C] Confirmed requirement (spec)
[P] Proposed design, not yet approved
[X] External dependency
[U] Unresolved decision
[F] Future phase
Index: how the set connects
A is the master map. B and C take a user from current reality to tasks. D sets resources for C. E handles reality changes for B and C. F feeds options into B. G expands on B. H sits beside C as a parallel track. I shows what runs offline under A. J is the journey through all of them.

Current reality to future vision map

Purpose: moves from the actual starting point toward larger goals through stage gates. Milestone ladder values are calculation steps, not forecasts. No financial outcome is guaranteed.

  CR["Current reality [C]"] --> BA["Baseline assessment [C]"]

  CG --> SO{"Strategic options: 2 to 3 routes [C]"}
  SO --> SP["Selected path, or customised path [C]"]
  SO -.->|"alternative route"| ALT["Alternative route [C]"]
  SP --> MS(["Milestone ladder: calculation steps [C]"])
  MS --> EX["Execution: tasks and habits [C]"]
  EX --> EV{"Evaluation at gate review [C]"}
  EV -->|"gate passed"| EXP(["Expansion to next gate [C]"])
  EV -.->|"reality changed"| SO
  RISK["Risks and stop criteria [C]"] -.-> EV
  DEP["Dependencies: relationships, assets [C]"] -.-> CG
  FINR["Financial requirements: runway, capital [C]"] -.-> CG
  TIMER["Time and energy limits [C]"] -.-> EX

E

Reality-change and adaptive planning loop

Purpose: handles a real-life event. The previous plan is kept as a version. Consequential financial or external actions wait for user approval.

flowchart TB
  EVT(["Real-life event: unexpected expense, lost time, new opportunity, failed milestone, new duty, market change [C]"])
  EVT --> REC["Record event [C]"]
  REC --> VAL{"Validate information [C]"}
  VAL -->|"unverified"| REC
  VAL -->|"verified"| AFF["Identify affected goals and tasks [C]"]
  AFF --> IMP["Calculate impact: dates, budget, risk [C]"]
  IMP --> ALTP["Generate up to 3 alternative plans [C]"]
  ALTP --> CMP["Compare trade-offs: plan diff [C]"]
  CMP --> APR{"User approval needed? [C]"}
  APR -->|"yes, for large or irreversible change"| UPD["Update plan as new PlanVersion [C]"]
  APR -->|"no"| UPD
  UPD --> HIS[("Previous plan kept, change history [C]")]
  UPD --> MON["Monitor results [C]"]
  MON -.->|"new event"| EVT
  EXT["Money or external action: never automatic [C]"] -.-> APR

Purpose: expansion depends on evidence and readiness. Not every business expands. Each stage has entry and exit conditions. Stages after G-F are unresolved until the owner decides on them.

flowchart TB

  NE -.-> IMR["International market research [F]"]

  CP --> IS(["International scale, owner approval [F]"])
  LV -.->|"no evidence: stay local"| CO
  CP -.->|"pilot fails: exit"| NE

J

Complete user journey

Purpose: the app guides the user to the next field, so they do not need to remember what to enter. Optional information can be added later without blocking other features.

flowchart TB
  OP["Open app [C]"] --> EXP["Explore prebuilt structure [C]"]
  EXP --> CP3["Create profile [C]"]
  CP3 --> GF["Complete guided fields [C]"]
  GF --> RB["Review baseline [C]"]
  RB --> CMPP["Compare recommended paths [C]"]
  CMPP --> SEL{"Select or customise plan [C]"}
  SEL --> EXE["Execute tasks [C]"]
  EXE --> REC["Record real-life events [C]"]
  REC --> RV["Review changes [C]"]
  RV --> AD["Adapt plan [C]"]
  AD -.->|"repeat"| EXE
  OPT["Optional fields, added later, never block other features [C]"] -.-> GF
